# @aether/twin-schema

One digital-twin data contract shared by the backend, Builder editor and public 3D viewer. This prevents saved geometry from being interpreted differently across the apps. It is a library, not a website or server.

- `src/index.js`: `assertCanonicalTwin`, `pointInPolygon`, `canonicalJson` and the exported schema. The API checks incoming/outgoing revisions, and the viewer/furniture path uses the same polygon contract.
- `src/index.d.ts`: `CanonicalTwinV1`, source/revision/geometry/correction types consumed by TypeScript apps.
- `schema/canonical.schema.json`: generated draft-07 JSON Schema, exported from `apps/ai-service/cad/schema.py`.

The JavaScript runtime and declaration file are paired because the same package runs in the Node API and bundles into the Next.js website. This avoids another build process or generated `dist` directory for a small library. Declarations describe the runtime and canonical data; they are required developer tooling, not duplicate application logic.

Public imports stay `@aether/twin-schema`. The schema is also available at `@aether/twin-schema/schema`. To regenerate it, run the repository Python virtual environment with `-B -m cad.schema` from `apps/ai-service`. Run `npm run test:canonical` after contract changes. Full topology/approval validation remains in Python; the shared library provides boundary checks, not a second DXF parser.

Ajv 6.12.6 is pinned. Its installed files are generated by npm and ignored, while the source and schema here are maintained. Do not change a validator version merely to reduce the visible folder count; review compatibility and run validation checks first.
